# Bounded native terminal/settings checks

QA sources live directly in this canonical project. Private runtime copies are generated only under build/local-mc-debug, with owner markers, actual client/server PIDs and creation times. No production configuration is modified.

run_native.py uses the installed sibling better-mc-remake local_mc_debug/runtime launcher and installed bmc5server/_client_test libraries. It loads the current terminal .3 and localization settings.3 artifacts plus pinned settings mods. Set MUXI_NATIVE_LAB to a fresh path below this project's build/local-mc-debug for each launch; an existing instance root is rejected. MUXI_TERMINAL_CANDIDATE can explicitly select a uniquely built candidate. Generate build/native-final/labels.json from the pinned actual mod language payloads before launch. Existing approved GIF/PNG bytes are read from the local historical media evidence path inside compile_agent; adjust that media input to the approved identical bytes when moving machines. Those are media fixtures, never source checkout or replacement product JARs.

control.py verifies the owner marker, stop/result files, live PID and matching creation time before writing and while waiting. Each callback stays tied to its runId, unique DOM evaluation tokens prevent stale matches, and controller-receipts.jsonl is append-only. Native individual receipts remain under coordinator. The default missing suite is remaining.py, which persists each check immediately and normally stops its lab after success. On an error it prints the exact pending item and leaves the bounded instance available for repair, subject to the launcher's900-second cap. It never sends a command to an exited lab.

The shop fixture replaces only games directory/context/invitation data through the mutable SDK invoke entry. games.request and games.snapshot are both handled. Image descriptors still run through real Java icons.get, ResourceManager and MCEF decoding. This is UI/resource acceptance, not gameplay or redemption acceptance. MUXI_RECHECK_SHOP=1 explicitly selects PNG/scroll checks when needed; the default does not repeat already accepted shop checks.

SettingsProbe uses actual native option Button.onPress and Iris screens. SettingsDrawMixin observes actual GuiGraphics caption draws; screenshots wait for resource-overlay fade. SettingsLifecycleMixin observes real reload futures and close state, without modifying candidate shutdown. Physical F3+T is sent only after the owned GLFW window has foreground. If its only loaded input layout intercepts Latin letters, the driver temporarily loads English for this window thread, then restores the original layout and unloads the temporary input. No preference/config file is written.

The QA-only MCEF checksum bypass uses the installed already-cached native library payload. It is embedded only in the QA agent. It is never packaged into the terminal or localization candidates. None of these callbacks establish SSO, deployment, full-pack gameplay or physical OS input except the explicitly recorded F3+T event.

Native outcomes and rejected intermediate candidates are recorded in docs/window-ui-native-20261013.md. After normal stop, match the observed helper identities and verify no residue, both JVM exit codes, port rebind and world-lock exclusive open. Force-cleaning an exact orphan must remain a failed normal-exit result.
