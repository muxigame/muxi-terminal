# 音乐目录时长过滤

资源目录仍只选择 `sounds/music/` 或包含 `/music/` 的 OGG 文件。明确的 `ambient`、`ambience`、`sfx`、`sound_effects` 目录被排除；曲名包含 ambient 不会单独被判作环境音。

`config/muxi_terminal/music-catalog.json` 的 `minTrackSeconds` 默认 10，可设 0–120；0 可关闭时长筛选。文件在首次后台扫描时创建。修改配置后在音乐 APP 刷新目录即可生效；格式错误会使用默认值，保留原配置文件。

后台只读取压缩 Vorbis 页的采样率和 granule 元数据。达到阈值就提前保留，不解码整个音乐库；短文件读到末尾确认长度。元数据未知的曲目保留，由真实播放器解码决定是否可用。没有执行全库无声检测，也不声称排除了静音录音。

缓存键含资源代际、实际资源包和文件 ID。普通目录刷新复用缓存，降低阈值也复用已有结果；提高阈值时重新检查不足以证明长度的前缀；资源包重载清空元数据缓存。`music.snapshot` 的 `catalogFilter` 提供最近一次扫描耗时、读取字节、过滤数和缓存命中。

2026-10-11 的无窗口真实资源审计包含 162 个音乐路径文件。10 秒阈值过滤 5 个 Boss 短引子、结束段和鼓点；20 秒会过滤 12 个，开始影响音乐片段。完整时长读取遍历约 756 MB、耗时约 8.2 秒；实际 Java 提前停止筛选约 139 毫秒、33.4 MB；重复检查命中 162/162、约 0.52 毫秒。这些是资产/JAR 元数据测量，MC 的资源管理器、增量发布和 UI 总耗时需另测。

音乐仲裁暂未修改。代码审计和实际服务状态谓词测试未发现“仅持有终端/打开 APP 就独占”的原因；停止、下载失败、手动暂停及自然背景音乐间隔的原生完整验证仍待独立 MC 窗口。只有实际证明误阻止背景音乐后，才按用户条件加入持有终端时的 Minecraft 集默认播放，避免干扰主动播放或暂停。
